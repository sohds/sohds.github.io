CASE 01 / PENSION AI AGENT

답을 못 찾을 때,
문서가 잘린 위치를 확인했습니다.

증권사 주최 연금 AI Agent 공모전
2026.07–09 / 3인 팀 / 기술 설계와 구현 총괄
전체 프로젝트 기여도 50% 초과

검색 상위에는 도입 문장만,
실제 사유 목록은 92위에 있었습니다.

중도인출 질문의 검색 결과를 직접 읽었습니다. 질문과 조건 목록이 서로 다른 청크로 나뉘어 있어, 상위 결과만 받은 모델은 필요한 근거를 찾을 수 없었습니다.

모델은 경계를 고르고,
코드는 원문을 보존하도록.

길이와 제목 중심의 분할을 의미 단위로 바꿨습니다. LLM은 분할 앵커를 선택하고 Python은 해당 위치의 원문을 추출하게 했습니다. 조건과 예외를 함께 담으면서 모델이 본문을 다시 쓰는 위험을 줄이기 위한 선택입니다.

RAG 문서 품질앵커 청킹PythonBM25 + RRF
검색 상위 / 도입 문장일정 조건을 충족하면 중도인출이 가능합니다.
92위 / 실제 사유 목록답변에 필요한 조건 목록이
다른 청크로 분리되어 있었습니다.

질문과 답의 조건이 갈리면, 상위 결과를 읽어도 답변할 수 없습니다.

하나의 의미 단위질문 + 적용 조건 + 예외
고객 질문에 답할 수 있는 범위로 묶기
역할 분리LLM → 분할 위치 선택
Python → 원문 그대로 추출

새 방식에서는 포함 구간과 사유가 있는 제외 구간을 구분해 확인했습니다.

실제 금융 원문을 복제하지 않은 구조 설명용 예시입니다.

설계를 검증한 범위와 지표의 의미

원문 16건같은 원문에 기존 규칙을 적용해 비교했습니다. 기존 방식에서 미설명 문자 유실 21.9%를 발견했습니다. 새 방식은 원문 포함과 사유 있는 제외를 구분합니다.

탐색 질문 8개Hit@5가 5/8에서 7/8로 높아졌습니다. 작은 탐색 표본이며 최종 평가와 구분합니다. 청킹 하나의 독립적 효과로 일반화하지 않습니다.

내부 평가 419문항팀이 만든 438문항 중 채점 대상에서 근거 문서 Hit@5 93.8%를 기록했습니다. 정답 문서의 검색 여부이며 답변 정확도는 아닙니다.

369건은 중복을 포함한 판정 수이며 35건은 문제 표시 수입니다. 서로 다른 결함 35개를 모두 수정했다는 뜻이 아닙니다.

검증 시점과 남아 있는 한계

459건의 실행 기록계산 모듈 마지막 수정 전의 전체 API 실행 기록입니다. 요청 실패가 없다는 것과 모든 답변이 금융적으로 정확하다는 것은 다릅니다.

수정 후 추가 확인관련 단위 검사 6종과 숫자 E2E 5건을 추가 확인했습니다. 최종 버전에서 전체 459건을 다시 실행한 것으로 쓰지 않습니다.

업데이트 검증에 적용같은 질문으로 전후 결과를 비교하되 검색, 답변 내용, 형식을 나눠 보겠습니다. 상용 모델 업데이트 운영 실적이 아닌 경험의 적용 방향입니다.
